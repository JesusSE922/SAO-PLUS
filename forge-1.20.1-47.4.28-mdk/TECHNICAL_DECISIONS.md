| 20 | **PROVISIONAL** curve `xp(L -> L+1) = round(100 * L^1.6)`; 2 points per level gained, +5 at every level multiple of 10; attribute base value 1, max 999. All in `ProgressionConfig`. | Assistant | 2026-11-09 |

| 22 | Each attribute stores `invested` (points actually paid); respec resets all attributes to base and refunds exactly that, so points cannot be duplicated. `rewarded_level` ensures a level is never rewarded twice. | Assistant | 2026-11-09 |
| 23 | No COL system exists. `CurrencyGateway` is the integration point; with none installed `respecAttributes` returns `NO_ECONOMY` and changes nothing (no simulated payment). Provisional cost 100 COL per level. | Assistant | 2026-11-09 |
| 24 | Server authority: all writes go through `ProgressionService` with `ServerPlayer`; no client-to-server packet, no command or debug tool. Experience sources (kills, quests...) are not implemented. | User brief | 2026-11-09 |

It is needed to read item weapon categories and recognize its damage sources. Supersedes decision 16 for Epic Fight only; RAS and Pufferfish stay undeclared. | Assistant, per user brief | 2026-11-09 |
| 26 | All Epic Fight code lives in `compat.epicfight`; `EpicFightCompat` (no EF types) guards `EpicFightAdapter`. A first version referenced EF types from the guard class and crashed the Core when EF was absent (found by a server test, fixed). | Assistant | 2026-11-09 |
| 27 | The Epic Fight weapon category (`epicfight:<name>`, e.g. greatsword) is exposed as an external category; weapon family data maps categories to families with `"categories"`. Items and tags win over categories. Which family owns which category is data, not code: none is shipped. | Assistant | 2026-11-09 |
| 28 | `CombatBridge` posts `PlayerAttackContextEvent` (level, attributes, family) for player melee hits and applies a damage multiplier that starts at 1.0. **PROVISIONAL / PENDING DESIGN:** no combat formula exists, so the Core never changes it. Mastery progress by hit stays removed (see 12). | Assistant | 2026-11-09 |
| 29 | Optional per-item `"stats"` in family data are stored as opaque numbers (`WeaponFamilyManager.statsOf`) and have no effect yet; their meaning is pending design. Epic Fight movesets for external weapons are mapped with Epic Fight datapacks (`capabilities/weapons`) or CompatLink, not by SAO+. | Assistant | 2026-11-09 |
| 30 | **First playable version (all PROVISIONAL, authorized by the user to be decided autonomously; all tunable).** Numbers live in `combat/GameplayConfig` (formulas in `CombatFormulas`); global scales `damageScale`, `experienceRate`, `colRate` in the server config `saoplus-server.toml`. Decision 12 (no mastery progress by hit) is **superseded** by 33; decision 28 (multiplier 1.0, no formula) is superseded by 31. | User directive | 2026-11-09 |
| 31 | **Combat formula.** Damage multiplier = level (+0.3% per level, +29.7% at 100) x Strength (+2% per effective point) x weapon `damage` x mastery rank (+1% per rank, max 10) x armed Sword Skill multiplier; the bonus part is scaled by `damageScale`; then a critical (chance 5% + 0.3%/Luck + 0.2%/Dexterity + weapon crit, cap 60%, x1.5) and weapon penetration (exactly compensates the vanilla armor reduction for that fraction). Effective attribute points count fully up to 30 and at 50% beyond (diminishing returns, same spirit as the cost softcap). Why: level gives a deliberately small bonus so it never replaces player skill (brief); enemy strength scales through floors, so levelling cannot trivialise combat. | Assistant | 2026-11-09 |
| 32 | **Weapon stats** (`WeaponProfile`, JSON `stats` per item or `family_stats` per family): `damage` multiplier; `speed` = attack-speed multiplier (item attribute modifier); `reach` = extra blocks (entity-reach modifier); `crit` = extra crit chance; `penetration` = fraction of armor ignored; `stability` = fraction of knockback ignored while held; `recovery` = fraction of Sword Skill cooldown removed (max 50%). Item stats override family stats. Shipped family defaults are placeholders. Stability/speed/reach are applied on the server only (the client has no family index), so the client may show slightly different attack-cooldown visuals. | Assistant | 2026-11-09 |
| 33 | **Weapon mastery.** +1 experience per hit and +3 per Sword Skill hit to the family of the main-hand weapon (melee and projectile). Rank = largest r in 0..10 with total XP >= 100 r^2 (derived, not stored, so retunable). Reaching a rank unlocks the Sword Skills of that family requiring it (`unlocked_techniques`); unlocking is also checked when a skill is used. | Assistant | 2026-11-09 |
| 34 | **Families <-> Epic Fight** (`data/saoplus/saoplus/weapon_families`): one_handed_sword = sword, uchigatana; two_handed_sword = greatsword, longsword, tachi; spears = spear, trident (+ Basic Weapons spear/glaive/quarterstaff); daggers = dagger; axes = axe; bows = bow, crossbow; hammers_maces = Basic Weapons hammer/club + item tag `saoplus:hammers_and_maces` (Epic Fight has no hammer category); dual_wield = tag `saoplus:dual_wield_weapons` and sword_shield = tag `saoplus:sword_and_shield_weapons` (empty tags: Epic Fight has no such categories; packs fill them; dual wield is meant to be exceptional per GDD 7.3 and has no unlock rule yet). | Assistant | 2026-11-09 |
| 35 | **Agility.** Passive evasion chance 0.1% per effective point (cap 25%) against hits by other entities; Sword Skill cooldown -0.4%/point (cap 40%, plus weapon recovery); windup -0.5%/point (cap 50%); combo window +0.1 tick/point (cap +20 ticks). Epic Fight's own dodge/guard/parry are untouched; hooking its events to agility is pending. | Assistant | 2026-11-09 |
| 36 | **Resources.** Max HP = vanilla + 0.5 per effective Vitality point + 0.1 per level (transient attribute modifier re-applied on login, respawn, dimension change, level up, spending). Max MP = 20 + 3 per effective Intelligence point + 0.5 per level; regenerates (1 + 2% of max) per second, applied every 10 ticks; full on respawn; stored in `ResourceData`. | Assistant | 2026-11-09 |
| 37 | **Sword Skills** (`data/<ns>/saoplus/sword_skills`): activate (key R, one contextual key, GDD 9.5) pays MP and starts the cooldown, windup, then the skill is armed for `window` ticks and the next hit executes it with its multiplier; using a skill listed in `combo_from` within 30 ticks (+agility) of the previous execution adds `combo_bonus`; pressing the key while armed cancels (50% MP back only during windup); damage during windup interrupts (no refund). Requirements: held weapon family, unlocked technique (mastery rank), level. Server state is in memory and resets on logout/clone. 18 starter skills (strike rank 1, combo rank 3 per family) are placeholders. | Assistant | 2026-11-09 |
| 38 | **Economy.** COL wallet in `ResourceData`; only `EconomyService` changes it. Sources: enemy kills (default 0.25 COL per base max health x level-gap factor x floor x `colRate`) and the operator command `/saoplus give`. Sinks: attribute respec (100 COL x level, via `CurrencyGateway`, now installed by `EconomyService`), `repair` (1 COL per missing durability) and `purchase`. No shops/blacksmith content. | Assistant | 2026-11-09 |
| 39 | **Enemies and floors.** Hostile mobs (`Enemy`) get health/damage multipliers from `enemy_profiles` and from the `floors` entry of their dimension (transient modifiers; spawn health set once). Rewards: XP 0.5 per base max health (or profile value) x level-gap factor (-10% per level beyond 5 levels above the enemy, min 10%) x floor x `experienceRate`. Floors map dimensions to floor numbers; the shipped mapping (Overworld = floor 1, Nether = 2, End = 3) is a placeholder so the system works without Aincrad content. Highest floor reached is stored per player. | Assistant | 2026-11-09 |
| 40 | **Quests / FTB.** No compile dependency on FTB Quests or FTB Teams. Quests give SAO+ rewards through FTB Quests' own command reward running `/saoplus give <player> experience|col|points <n>` (operator level 2, not usable by players). Sharing XP inside FTB Teams parties is NOT implemented. | Assistant | 2026-11-09 |
| 41 | **UI.** HUD (level, XP bar, MP bar, COL, free points) and character screen (key K: level/XP/resources/attributes with "+" buttons/respec/weapon mastery), key R for skills. The only client-to-server message is `ClientRequestPacket` (SKILL, SPEND one point, RESPEC); everything is validated server-side. Network protocol raised to "2". | Assistant | 2026-11-09 |
| 42 | **Division of work (modpack principle, user directive).** SAO+ owns RPG logic: progression, attributes, combat formulas, mastery, Sword Skills, specializations, economy, rewards, floor rules. The modpack supplies: animations and combat mechanics (Epic Fight), weapons (Simply Swords, Basic Weapons), quests (FTB Quests), parties (FTB Teams), world generation, structures and mobs (any worldgen/mob mod through datapacks). SAO+ adds a feature only where no mod of the pack does it. | User | 2026-11-09 |
| 43 | **Recursion with Epic Fight capabilities (stability).** Attribute-modifier lookups call `WeaponFamilyManager.statsOf`, which may query Epic Fight item capabilities, which could re-enter `ItemAttributeModifierEvent`. Fixed by a per-thread re-entrance guard plus a per-item profile cache that is dropped on datapack reload (`CombatRules.modifierProfile`). Not reproduced in game; the guard is preventive. | Assistant | 2026-11-09 |
| 44 | **Agility on Epic Fight (verified API 20.14.17, `PlayerEventListener`).** Epic Fight keeps dodge, guard, parry, stun and stamina. SAO+ only hooks: `STAMINA_CONSUME_EVENT` (cost -0.4% per effective Agility point, cap -40%), `MODIFY_ATTACK_SPEED_EVENT` (+0.2% per point, cap +20%) and `DODGE_SUCCESS_EVENT` (opens a 40-tick counter window: next hit x1.25). The passive evasion chance of decision 35 stays for vanilla/other damage. Listeners are (re)registered on login, respawn and dimension change. Stun duration and parry windows are not modified (no safe API found). | Assistant | 2026-11-09 |
| 45 | **Sword Skill presentation.** Skill data may name an Epic Fight animation (`epicfight:biped/combat/...`), a sound and a particle. The animation plays through `ServerPlayerPatch.playAnimationSynchronized` at activation (registered by the Epic Fight adapter via `SkillPresentation`); sound and particles are server-driven and need no client code. Unknown ids are ignored. Skills may also `heal` and add `knockback`. Which Epic Fight animation fits which skill is a placeholder choice. | Assistant | 2026-11-09 |
| 46 | **Specializations are functional.** `data/<ns>/saoplus/specializations/*.json` define branches with multipliers/bonuses and an obligatory drawback (loader warns otherwise). Requirements: level, family mastery rank; switching from another branch costs `switch_cost_per_level` x level COL (first choice free). Effects scale from 50% to 100% as the branch earns its own experience (1 per hit while active, rank r at 50 r^2). Inactive branches keep progress and apply nothing (GDD 6.3). Each branch has one exclusive skill that needs it active. Shipped: 2 branches per family (assault: damage/crit up, dodge/stability down, slower skills; guardian: stability/dodge up, damage down). | Assistant | 2026-11-09 |
| 47 | **Family rules.** `unlock` (level + mastery ranks of other families) and `composite` (main-hand families + off-hand shield or weapon families) in the family data. `WeaponResolver` resolves the active family: sword and shield = a one-handed sword with a shield in the off hand; dual wield = one-handed sword/dagger in both hands, unlocked at level 30 with one-handed sword mastery 5 (GDD 7.3: earned, not given; exact rule provisional). A locked family counts as no family. | Assistant | 2026-11-09 |
| 48 | **External weapons.** Explicit item lists in the family files for Simply Swords (typed weapons by suffix: chakram/sai = daggers, claymore/scythe/longsword/twinblade = two-handed, cutlass/rapier/katana = one-handed, glaive/halberd/warglaive/spear = spears, greataxe = axes, greathammer = hammers) and Basic Weapons (club/hammer = hammers/maces, dagger, spear/glaive/quarterstaff = spears), plus Epic Fight movesets shipped as `data/<mod>/capabilities/weapons/<item>.json` (club -> sword preset, hammers -> greatsword preset because Epic Fight has no hammer preset). Simply Swords unique/legendary weapons are NOT mapped except magiscythe, magispear, magiblade, mjolnir. Mappings for items of absent mods are harmless (checked: no errors with and without the mods). | Assistant | 2026-11-09 |
| 49 | **Economy.** Shops and blacksmiths are data (`data/<ns>/saoplus/shops`): buy offers (price, min level, min floor), sell prices, repair at a per-durability price. The entry is the `saoplus:merchant` / `saoplus:blacksmith` block (block entity tag `shop`); `ShopService` keeps a server session (shop + position) and validates distance (8 blocks) for every buy/sell/repair. The client only sends the offer index. Prices and stock are placeholders. | Assistant | 2026-11-09 |
| 50 | **FTB Teams.** Optional compile-only dependency; `FtbTeamsAdapter` installs the party provider (online team members, same dimension, within 48 blocks). Party members get 60% of the kill experience and 50% of the COL (each, at their own level-gap factor) and clear the floor together when a boss dies. | Assistant | 2026-11-09 |
| 51 | **FTB Quests.** Native reward type `saoplus:reward` (experience, COL or attribute points) registered in `RewardTypes`, selectable in the quest editor; `/saoplus give` remains only as an operator tool. Quest tasks are not duplicated: FTB Quests already provides kill, item, location and advancement tasks. | Assistant | 2026-11-09 |
| 52 | **Aincrad structure.** Floors are dimensions (`saoplus:aincrad_N`, skeleton worldgen: one fixed biome on the overworld noise, to be replaced by the pack's worldgen); `floors` data gives required level, recommended level, scaling and `requires_previous_clear`. Access is enforced on dimension travel (`EntityTravelToDimensionEvent`) and by the `saoplus:gate` block (teleport gate, block entity tag `floor`). Bosses are enemy profiles with `boss_floor`: killing one clears the floor for the killer and their party and unlocks the next floor. Vanilla Overworld/Nether/End are no longer mapped to floors. | Assistant | 2026-11-09 |
| 53 | **Zones.** `data/<ns>/saoplus/zones`: `town` = safe zone (no damage to players, no hostile mobs may join), `field`, `dungeon`, `labyrinth` = multipliers on mobs spawned or killed inside. Boxes are placed by whoever builds the towns/dungeons (structure mods, datapacks). Shipped: a town (96x96 around 0,0) and a labyrinth box per floor as placeholders. | Assistant | 2026-11-09 |
| 54 | **Interface.** SAO-styled HUD (level, HP, MP, XP bar, COL, free points) and a four-tab character screen (K): Status/attributes, Skills (unlock state), Branches (select, effects), World (floors: cleared/reached/locked). Shop screen. Catalog data reaches the client in a read-only `CatalogPacket` (login and datapack reload). Protocol version "2". | Assistant | 2026-11-09 |
